## How the work connects

Shayan and Ryea connect recommendations to validated proposals and the reversible Linux lifecycle. pp_response_engine.py coordinates state; the broker and fixed operation catalogue provide enforcement. frontend/src/main.jsx and actions.jsx connect the operator to those separately checked steps.

Mohamed and Martin connect labelled traffic cases to packet/log observations and original records. Mixed TCP/UDP and reply-direction cases test whether valid neighbours and service roles survive processing. Evidence views consume those observations; they do not create new traffic facts.

Laurence and Antonio connect persistence, streamed jobs, cancellation and export to reproducible tests and evaluation. Protocol acceptance, extraction agreement, model meaning and actual network effects remain separate evidence categories.

Additional links matter: the investigator uses Martin's log/evidence tools; the frontend assembles all members' source files; model evaluators use Mohamed's cases and Shayan's checked investigator. These are upload allocations and component dependencies, not a substitute for a member's own review or activity record.

## Upload and later integration

From the repository root, upload the contents of each UPLOAD TO GITHUB folder. Keep nested paths intact and include root dotfiles. Matching file paths are updated, new files are added and unrelated files remain. One commit message covers a batch. Use direct commit only if permitted; otherwise the site offers a branch/pull request route.

The current web/react/index.html references this release's hashed assets. Uploading new assets does not remove old hashes. Any obsolete-asset cleanup is a later explicit integration task, after confirming what the active index references. Do not delete legacy web/index.html, web/app.js or web/style.css merely because React is the normal current interface; compatibility routes are retained.

Keep member guides, instructions and screenshots outside the repository upload payload. No credentials, live histories, runtime databases, environments or private provider traces belong in the release. Licences and copied-component notices stay with the source/build.
