# Safe Network Response and Control

Role member: Ryea Dsouza.

pp_policy.py retains the older preview-only CLI policy. The current browser response path uses pp_response_engine.py, pp_linux_lab.py, pp_response_broker.py and pp_response_client.py. Install the privileged service explicitly using install_response_service.py and packetpilot-response.service.

pp_response_operations.py defines fixed parameter checks and command templates. Broker-issued current lab captures support a temporary block of 10.77.0.20 to 10.77.0.10 TCP/8080 or a rate limit on service replies to that source. Durations are 5-120 seconds and rates 256-2048 kbit/s.

Proposals bind the exact capture, lab generation, recommendation and parameters. Separate operator approval is required; the model cannot execute arbitrary suggestions. Uploaded/historical captures do not gain live authority.

Verification checks selected-client effect, independent control traffic and restoration. Owned rules/qdisc state, manual rollback, independent expiry and restart recovery support reversibility. A failed restoration disables new actions while recovery is retried.

See [setup](../../docs/LINUX_RESPONSE.md) and [operation/verification limits](../../docs/WORKSPACE_RESPONSE_V4.md). Portable tests use lab doubles; actual Linux effects are separate retained experiments.
